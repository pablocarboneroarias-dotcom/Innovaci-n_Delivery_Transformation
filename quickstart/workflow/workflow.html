Architecture & Delivery Engine

Spec-Driven Development (Spec Kit) & 7-Stage SDD

This comprehensive guide walks you through the 7-stage Spec Kit delivery lifecycle, the 8 core principles of the EBOAP Constitution v1.3.0, mandatory Nebula Logger observability, and automated Quality Gates.

1. Stage 1: Constitution & Governance

The Constitution (.specify/memory/constitution.md) establishes the supreme architectural guidelines: Salesforce-First hierarchy, mandatory Nebula Logger, ≥85% test coverage, and human-gated AI delivery.

/speckit.constitution

2. Stage 2: Specify Requirements (spec.md)

Transforms raw requirements or Figma design tokens into structured user stories with Gherkin acceptance criteria (Given-When-Then).

/speckit.specify
Create a feature specification for the Customer Energy Move-In workflow.

3. Stage 3: Clarify & Ambiguity Resolution

Identifies underspecified areas by asking up to 5 targeted clarification questions and encoding answers back into spec.md.

/speckit.clarify

4. Stage 4: Implementation Planning (plan.md)

Generates the architectural blueprint adhering to the Salesforce-First preference hierarchy (Standard $ ightarrow$ Declarative $ ightarrow$ Metadata $ ightarrow$ Flow $ ightarrow$ Apex).

/speckit.plan

5. Stage 5: Task Breakdown & Checklist (tasks.md)

Decomposes the plan into 4 phased, dependency-ordered tasks: Phase 1 (Setup), Phase 2 (Foundational), Phase 3+ (User Stories), Phase 4 (Polish & Quality Gates).

/speckit.tasks
/speckit.checklist

6. Stage 6: Cross-Artifact Analyze Gate

Performs non-destructive quality analysis across spec.md, plan.md, and tasks.md to guarantee 100% requirement coverage before coding starts.

/speckit.analyze

7. Stage 7: Implementation, Testing & Convergence

Executes tasks step by step: generating bulkified Apex, accessible LWCs, unit tests, running Code Analyzer, and converging unbuilt tasks.

/speckit.implement
/speckit.converge

The 5 Quality Gates (Constitution v1.3.0)

  1. Static Analysis Gate: Salesforce Code Analyzer scan must be free of Critical and High violations (PMD, SFGE, ESLint).
  2. Coverage Gate: Apex tests must achieve $ge 85%$ code coverage with 200+ bulk record assertions; complete Jest coverage on LWCs.
  3. Environment Gate: Metadata must validate with dry-run deploy (sf project deploy validate) on target sandbox.
  4. E2E Gate: Automated Playwright browser test suite verifies full user journeys against acceptance criteria.
  5. Release Verification Gate: Formal sign-off verifying translations (EN/SV), Nebula Logger readiness, and human authorization.

Nebula Logger Standards (Principle IV)

All custom Apex, LWC, and Flow logic must log through Nebula Logger:

// Apex Logging Standard
Logger.info('Starting Move-In processing for Account: ' + accountId)
      .setRecord(accountId)
      .setScenario('MoveIn_Onboarding');
Logger.saveLog();

Git Conventions & Traceability

  • Branch format: feature/{slug-number}_{YYYYMMDD}_{slug-description} (e.g., feature/us-104_20260904_customer-move-in)
  • Commit format: [{slug-number}] {type}: {subject} (e.g., [us-104] feat: implement move-in controller)
