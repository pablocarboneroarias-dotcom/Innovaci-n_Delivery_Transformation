Frequently asked questions

Short answers with links to the full guides. This workspace is for the whole delivery team, not just developers. If your question is not here, use the search box above or ask in the team channel.

Who is this for?

Is this only for developers and technical people?

No. This is the most common misconception about the workspace. It is built for the whole delivery team: product owners, business analysts, QA, project managers, scrum masters, release managers, and developers. Most skills produce business artefacts such as user stories, test cases, release notes, meeting summaries, and status updates, not code. There are dedicated guides for product owners and QA alongside the developer guide.

I am not technical at all. Can I really use this?

Yes. Day-to-day use is a chat panel where you type plain English, the same way you would write a Teams message. No coding, no command line, no special syntax. The one-time setup is the only technical-looking part, and the getting started guide walks through it step by step with copy-paste commands.

Do I need to know how to code?

No. Coding skills exist for developers, but you never need to touch them. Describe what you want ("summarise this meeting", "draft a user story for X", "check this work item against the template") and the workspace routes your request to the right workflow automatically.

What can a product owner, business analyst, or project manager do with it?

Turn meeting transcripts into action items and draft stories, write and refine user stories with acceptance criteria in the team format, build and prioritise backlogs, check new requests against the project scope, validate work items against the golden templates, generate release notes, and draft stakeholder emails and ADO comments. The product owner guide has worked examples.

How is this different from ChatGPT or a plain chatbot?

It knows this project. Team conventions, work item templates, the ADO project, the wiki, roles, and the project's GenAI use policy are built in, so the output matches how this team actually works. A generic chatbot knows none of that, and it has none of the safety guardrails this workspace enforces on every interaction.

Getting started

How do I get started, step by step?

Three steps. First, install the tools from the install guide (copy-paste commands for every platform). Second, clone the repository and open the workspace in VS Code. Third, open Copilot Chat and type "what can you do": the workspace lists what is available for your role and you take it from there. There is also a guided workspace-setup skill that checks prerequisites and walks you through the whole thing.

I have never used VS Code. Is that a problem?

No. VS Code is just the app the chat lives in. You do not need to write or read code in it: you open the workspace once, open the Copilot Chat panel, and type. The getting started guide shows exactly where to click.

What should I try first?

Something low-risk with an immediate payoff: paste a meeting transcript and ask for action items, ask "who does what on the team", or ask it to quality-check one of your work items. Nothing you type can change an external system without asking you first, so you can explore freely.

What is this workspace?

A VS Code workspace for the KAB DNA delivery team with AI skills, agents, and safety guardrails built in for GitHub Copilot Chat. It covers the whole delivery lifecycle: discovery, backlog, development, QA, and release. Start with the getting started guide.

What do I need installed?

Git, Node.js (18+), Python 3.11+, jq, Salesforce CLI, and VS Code with the Copilot extensions. The install guide has copy-paste commands for macOS, Windows, and Linux.

Does everything work on Windows?

Yes. All safety hooks and tooling scripts are cross-platform and need only Node. Verify on your machine with node tooling/scripts/hooks-smoke-test.js: it should report all hooks passing. One Windows note: the Python launcher is python, not python3.

How do I connect to a Salesforce org?

Authenticate with the Salesforce CLI and set a default org. No org alias is hardcoded anywhere: skills read the connected org from sf config get target-org and confirm with you before any org operation. See Step 3 of the setup guide.

What are the knowledge repos under project-knowledge/?

Read-only knowledge repos (best practices, project wiki, source code mirrors) mounted at project-knowledge/. They are gitignored and cloned once during setup; the expected entries live in workspace.yaml and a session-start hook validates they are present.

Using it day to day

Do I need to learn special prompts or commands?

No. Plain English works: ambiguous requests are routed through the skill-finder skill to the right workflow. Slash commands such as /web-sync are shortcuts for people who use a skill often, never a requirement.

Can I break something by asking the wrong question?

No. Questions and local drafts are always safe. Anything that would change an external system (an ADO work item, a Salesforce org, an email) requires your explicit confirmation first, and destructive commands are blocked outright by the safety hooks. The worst outcome of a bad question is an unhelpful answer.

What if the AI gets something wrong?

You are always the reviewer. Every output is a draft until you approve it; nothing lands in ADO or Salesforce without your say-so. If an answer looks wrong, say so in the chat and it corrects course. If a skill repeatedly produces wrong output, raise it with the team so the skill can be fixed at the source.

What everyday tasks does it handle well?

Turning meeting transcripts into actions and stories, drafting user stories with acceptance criteria, refining and quality-checking backlog items, generating test cases, writing release notes, drafting persona-aware emails and ADO comments, checking scope against the contract, and answering process questions like "who approves a release". Browse the skills catalogue by delivery phase to see everything.

How do I know the answer is based on real project data and not made up?

Skills read live sources (ADO work items, the wiki, repo files) rather than relying on the model's memory, and the workspace rules require the assistant to say "I don't know" instead of guessing. When an answer cites a work item or file, you can follow the reference and check it yourself.

Skills & agents

What is a skill and how do I run one?

A skill is a structured workflow defined in a SKILL.md file under .github/skills/. You trigger it in Copilot Chat with a slash command (for example /web-sync) or by describing what you need in plain English. Browse the skills catalogue.

What is the difference between a skill and an agent?

A skill is a step-by-step workflow the main assistant follows. An agent is a specialised sub-assistant (for example a read-only ADO scanner) that skills or you can dispatch for a focused job. See the agents catalogue.

I don't know which skill to use. What do I do?

Just describe what you need in Copilot Chat. The workspace routes ambiguous requests through the skill-finder skill, which maps plain-English asks to the right skill. Asking "what can you do" also works.

How do I add my own skill?

Create a folder under .github/skills/<name>/ with a SKILL.md (frontmatter with name + description, then the workflow). Only references/, scripts/, and assets/ subfolders are allowed. Validate with node tooling/scripts/validate-skills.js, then run /web-sync so it appears on this site.

How does the website stay in sync with the skills?

The /web-sync skill parses every SKILL.md and agent file and regenerates the site data files and stats. Run it after adding or changing a skill, agent, or hook.

Safety, security & governance

Where do my conversations go? Is my data safe?

The workspace runs on GitHub Copilot inside VS Code, so the terms of KAB's Copilot agreement govern how prompts and responses are handled. Locally, safety hooks block credential file reads and secret writes, and session events go to a hash-chained audit log on your machine. See the governance page for the full posture.

Can I paste customer or personal data into the chat?

No. The workspace rules keep customer, employee, contract, pricing, and personal data out of AI context; use synthetic test data instead. Any new personal data element in the solution itself must first be registered in the GDPR data register. When in doubt, leave the data out and ask the team.

Is this going to replace my job?

No. It drafts, you decide. The project's GenAI use policy requires a human to validate every AI output and forbids AI from making final business, customer, or contract decisions. Treat it as a fast assistant that takes the repetitive part of the work; the judgment, the context, and the accountability stay with you.

Who is accountable for what the AI produces?

The person who uses it. Every output requires human review before it is used, and AI-generated content shared externally must carry a disclosure. The AI never signs off on anything; you do.

What if I see an answer that is wrong, biased, or inappropriate?

Do not use it, and report it. In the chat you can simply say the output is wrong and ask for a correction. For recurring or serious issues, raise it with the delivery team lead so it can be logged and addressed at the source.

What stops the AI from doing something destructive?

Safety hooks: small Node scripts that run before and after every tool call. They block destructive shell commands, credential file reads, and secret writes, and require confirmation for external mutations (ADO, Salesforce, email). See the full hook list.

Can the AI read my .env file or other secrets?

No. The block-credential-file-read hook blocks reads of .env variants, private keys, SSH and cloud credential files, and the guard-sensitive-files hook blocks writes to them. This applies on all platforms.

Will the AI change Azure DevOps or Salesforce without asking?

No. All external mutations (ADO work item writes, deployments, emails, PRs) require explicit confirmation first. Local file reads and writes auto-execute; anything that leaves the machine asks.

Where is AI usage and cost tracked?

The cost ledger hook logs token spend to ~/.cache/copilot/cost-ledger.md (macOS/Linux) or %LOCALAPPDATA%\copilot\cost-ledger.md (Windows). Session events go to a hash-chained local audit log; summarise it with node tooling/scripts/export-audit-log.js.

Is this compliant with the project's AI policy and the EU AI Act?

The workspace enforces the GenAI use policy on every interaction (blocked and warned action classes), keeps an AI Act risk register and a GDPR data register, and requires human review of all AI output. AI-generated content shared externally must carry a disclosure.

Delivery workflow

What is the work item hierarchy?

Epic → Feature → User Story, never skipping a level. The User Story is the leaf deliverable; Tasks are not created. See the 7-stage workflow.

What is the commit message format?

Every commit must start with US#<ID> referencing the user story. This is enforced by commitlint, so a commit without it is rejected.

Where do deployments to SIT, UAT, and Production run?

Only through the ADO pipelines, never from a local CLI. Local development uses scratch orgs, which you can create and manage with the scratch org skills.

Is there a guide for my role?

Yes: developers, product owners, and QA, plus per-role journey pages linked from My Project.

Troubleshooting

A hook or script fails on my machine. What first?

Check node --version (needs 18+), then run node tooling/scripts/hooks-smoke-test.js from the repo root. If a specific hook fails, include its name and the output when you ask for help.

Copilot says a command or tool was blocked. Why?

A safety hook intervened: the message names the hook and the reason. This is by design for destructive commands, credential files, and unconfirmed external mutations. If you believe a block is wrong, raise it with the team; do not bypass the hook.

The skill I ran behaved differently than the docs describe.

The SKILL.md in the repo is the source of truth: the assistant always re-reads it before executing. If the website is stale, run /web-sync; if the skill itself is wrong, fix the SKILL.md and validate with node tooling/scripts/validate-skills.js.

Search on this site returns nothing for a new page.

The search index is generated. Rebuild it with node docs/assets/js/build-search-index.js from the repo root and reload the page.

Who do I ask when I am stuck?

Ask in the team channel, or use the search box at the top of this site to find the relevant guide. My Project shows who owns what if you need a specific person.
